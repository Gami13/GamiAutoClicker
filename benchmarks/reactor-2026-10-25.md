# Reactor comparison — 2026-10-25

The port was measured as a Release x64, managed, unpackaged, self-contained build with `Microsoft.UI.Reactor 0.1.0-preview.16`. The original baseline used the same deployment shape, .NET 10, Windows App SDK 2.4.0, and the same sampler. These are idle windows with clicking disabled, not Native AOT or a packaged installation.

The sampler started three fresh processes per scenario, waited for the ready marker, warmed up for 10 seconds, then sampled once per second for 30 seconds. Values below are the medians of the three run medians. CPU is process time as a percentage of one logical core. Task Manager Memory is private working set, not total process working set.

| Scenario | Build | Task Manager Memory | Private commit | Total working set | One-core idle CPU |
| --- | --- | ---: | ---: | ---: | ---: |
| Main | Original | 41.4 MB | 104.7 MB | 149.4 MB | 1.65% |
| Main | Reactor | 39.8 MB | 103.7 MB | 154.8 MB | 3.46% |
| Settings open | Original | 52.4 MB | 117.6 MB | 169.5 MB | 2.27% |
| Settings open | Reactor | 46.6 MB | 109.8 MB | 167.7 MB | 2.84% |

The Reactor build used about 1.6 MB less private working set on the main window and 5.8 MB less with settings open. This is the Task Manager Memory counter; total working set on the main window was 5.4 MB higher because it also counts resident shared pages. The 30-second CPU averages were higher, but they varied materially (Reactor main 2.89-4.85%; settings 1.60-3.20%). In the first Reactor main run, 0.83 CPU seconds occurred in the first 10 measured seconds and only 0.05 in the last 10, even after warmup. This is evidence of transient work, so these short runs do not establish a steady idle CPU regression or its cause. Active clicking and visible interactions were not measured.

The three-run measurements preceded the final changes that embedded translations and updated the backdrop on focus/theme changes. A later environment switch removed the .NET 10 SDK used for the original build, so the final unpackaged rebuild could not be completed. The attempted follow-up samples were taken after an MSIX build had reused the output directory; both are excluded rather than mixing deployment shapes. Repeat the comparison on a stable SDK/toolchain before treating small differences as conclusive.

See [the original baseline](baseline-2026-10-24.md) and [the sampler](Measure-Process.ps1). The per-second data and full run summaries are in ignored `benchmarks/results/reactor/` and `benchmarks/results/reactor-final/` in this workspace. To repeat with the port:

```powershell
.\benchmarks\Measure-Process.ps1 -Executable .\GamiAutoClicker.Reactor\bin\x64\Release\net10.0-windows10.0.26100.0\win-x64\GamiAutoClicker.Reactor.exe -Scenario main -Runs 3
.\benchmarks\Measure-Process.ps1 -Executable .\GamiAutoClicker.Reactor\bin\x64\Release\net10.0-windows10.0.26100.0\win-x64\GamiAutoClicker.Reactor.exe -Scenario settings -Runs 3
```
