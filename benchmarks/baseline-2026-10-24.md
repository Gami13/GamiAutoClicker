# GamiAutoClicker baseline — 2026-10-24

Commit `a531b0c`; Release x64; .NET 10; Windows App SDK 2.4.0. This is a managed, unpackaged, self-contained test build (`WindowsPackageType=None`, `WindowsAppSDKSelfContained=true`), because the normal packaged build could not activate its Windows App SDK runtime in this sandbox. It is not the Native AOT distribution. The only source addition is the `PERF_BENCHMARK` conditional startup switch for opening the settings window and emitting a ready marker.

The [measurement script](Measure-Process.ps1) launched a fresh hidden process for each run, waited for its main window and ready marker, allowed 10 seconds to settle, and sampled every second for 30 seconds. Clicking remained disabled. CPU is process CPU time over the measured wall time, expressed as a percentage of **one logical CPU**, not Task Manager's overall CPU percentage.

| Scenario | Run | CPU seconds / 30 s | One-core CPU | Private working set MB | Private commit MB | Total working set MB |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Main window | 1 | 0.44 | 1.45% | 41.4 | 104.0 | 149.4 |
| Main window | 2 | 0.50 | 1.65% | 41.4 | 104.8 | 149.3 |
| Main window | 3 | 0.52 | 1.70% | 41.4 | 104.7 | 149.5 |
| Settings open | 1 | 0.41 | 1.34% | 52.4 | 117.9 | 169.5 |
| Settings open | 2 | 0.78 | 2.58% | 52.7 | 117.6 | 169.8 |
| Settings open | 3 | 0.69 | 2.27% | 52.4 | 116.0 | 169.5 |

Memory columns are medians of 31 one-second samples in each run. The **private working set** is the counter comparable to Task Manager's default Memory column. It was 41.4 MB for the main window and 52.4 MB with settings open (median across runs). Private commit is committed memory that cannot be shared; total working set includes resident shared pages, such as DLLs. The previous version of this report called the latter two figures “RAM used,” which was misleading.

The script also records peaks, handles, threads, and each raw sample in `benchmarks/results/` (ignored by Git). To repeat the same scenarios with the current benchmark build:

```powershell
.\benchmarks\Measure-Process.ps1 -Executable .\GamiAutoClicker\bin\perf\GamiAutoClicker.exe -Scenario main -Runs 3
.\benchmarks\Measure-Process.ps1 -Executable .\GamiAutoClicker\bin\perf\GamiAutoClicker.exe -Scenario settings -Runs 3
```

This measures hidden, idle windows. Active clicking, visible rendering, and the intended packaged/Native AOT build require their own controlled runs. A Reactor port can implement the same `GAMI_PERF_SCENARIO` and `GAMI_PERF_READY_FILE` contract to use the same external sampler.
